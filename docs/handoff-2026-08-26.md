## The one constraint that will bite

`mobile/app.json` sets `runtimeVersion: { policy: "appVersion" }`, so the
runtime version *is* `expo.version`, currently `1.0.3`.

**Publish #47 with `eas update --channel production` and leave `expo.version`
at `1.0.3`.** Bump it and the update becomes invisible to every 1.0.3 install
on the store — which presents exactly as "the OTA didn't work".

No app code imports `expo-updates`, so it's stock behaviour: the bundle
downloads in the background and applies on the next cold start (users see it on
their second launch). This would be the project's **first ever** OTA push — test
on the `preview` channel first.

A TestFlight build needs none of this: `eas build` embeds whatever JS is in the
tree, so a build consolidates automatically. The risk runs the other way — an
OTA published from a branch never merged to `main` gets silently lost on the
next build from `main`. **Every OTA must also land on `main`.**

## Verified facts — don't re-derive these

- **OSHB tags word language in its morph codes** (`H…` Hebrew, `A…` Aramaic).
  Checked against `wlc/Dan.xml`: Dan 1:1 and 2:3 are `H`, **Dan 2:4 is mixed
  `A`/`H`** (the 2:4b switch), Dan 2:44 and 7:13-14 are pure `A`, Dan 8:1 back
  to `H`.
- Regenerating `original-verses.json` changes **exactly 3 of 234** entries, and
  every verse's text is **byte-identical** (asserted against the old file).
- **DRC1752 (YouVersion 55) uses Vulgate psalm numbering.** Evidence:
  `bible.com/bible/55/PSA.23.1-6.DRC1752` renders *"For he hath founded it upon
  the seas… Who shall ascend into the mountain of the Lord"* — Psalm **24** in
  Hebrew numbering. A naive DRC link for the tour's "Psalms 23:1" opens the
  wrong psalm. Hence the Hebrew→Vulgate map in `app/lib/translations.js`.
- **YouVersion IDs**: DRC1752 = `55`, NABRE = `463`, NRSV-CI = `2015`.
- **Bible Hub interlinear URLs confirmed against live pages**: `john/3-16.htm`,
  `genesis/1-1.htm`, `1_john/3-16.htm`, `songs/5-16.htm`, `psalms/127-1.htm`.
  `Song of Songs → songs` is the only slug override; the rest derive from
  numericSlug with underscores. **The derived ones are inferred from that rule,
  not individually verified** — worth spot-checking a couple locally, where
  biblehub.com isn't blocked.
- **Nothing has ever been OTA'd.** `expo-updates` and the `updates` config both
  landed in #35 (`27ed7e1`), *before* the 1.0.3 release bump; there are **zero**
  commits touching `mobile/` on `main` after `4f5429d`; no `eas update` anywhere
  in scripts, docs or CI. So `main`'s mobile code == what's inside build 1.0.3.
- **`66` is load-bearing.** `TOTAL` drives the progress percentage, and
  milestone thresholds are hardcoded `17/33/50/66` in **both** `app/page.js` and
  `mobile/lib/milestones.ts`. Extending `BASE_BOOKS` would silently un-complete
  everyone who finished the tour.
- **`eng-dra.zefania.xml` in `seven1m/open-bibles` is unusable** as a Catholic
  source: missing Sirach, 1 Maccabees and the Esther additions; includes Psalms
  of Solomon; 152 psalm chapters. Use eBible.org's WEB Catholic Edition
  (`eng-web-c`) or thedouayrheims.com (CC0) instead.

## Parked, with reasons

- **Deuterocanon** — a product decision, not an engineering one. No reading plan
  exists for those books (Whitman's is 66), and `66` is hardcoded as above. If
  it happens it needs its own opt-in track with a separate counter, never an
  extension of `BASE_BOOKS`.
- **Orthodox inline text** — genuinely unavailable. No licensable modern English
  Orthodox Bible has a data feed. Orthodox Study Bible is closed (Thomas
  Nelson), EOB is a PDF. Brenton's Septuagint (public domain) is a partial
  answer: right textual tradition, Victorian English, OT only.
- **No CI in this repo at all** — no `.github/workflows`. The only PR check is
  Vercel's preview deploy.
- **A `CLAUDE.md` release note** was offered and not written. Would cover the
  `runtimeVersion` trap, the OTA-must-merge-to-`main` rule, and the `eas.json`
  gotchas below.

## eas.json gotchas

- `cli.appVersionSource` is **`"local"`** — versions come from `mobile/app.json`.
  The vendored skill in #48 supplies a template that sets it to `"remote"`;
  letting it rewrite `eas.json` would desync the version and can strip an OTA of
  its audience. `mobile/eas.json` is hand-maintained. See
  `.claude/skills/eas-testflight/PROVENANCE.md` on that branch.
- `submit.production.android.serviceAccountKeyPath` points at
  `/Users/adambrown/.config/bible-tour/play-service-account.json` — machine-local,
  so `eas submit` for Android only works from your Mac.
- `build.production.autoIncrement` is on, so a build writes `buildNumber` back
  into `app.json` and leaves a local diff to commit.

## Tooling notes

- **Official Expo skills plugin** exists and is a better fit than the vendored
  one: `claude plugin install expo@claude-plugins-official`. Covers

  Expo managed project with no committed `.xcodeproj`. If you install it, scope
  the ASC API key down and pin to a commit rather than tracking `main`.
